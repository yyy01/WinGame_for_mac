# 架构与清单 v1

## 数据边界

| 层 | 内容 | 存放位置 |
|---|---|---|
| 公共清单 | 游戏 ID、相对 exe、参数、App ID | 仓库 examples 或用户自己的清单 |
| 私有注册 | 绝对路径、文件指纹、封面路径、运行时选择 | 本机 Application Support |
| Wine 会话 | prefix、注册表、Steam 登录、游戏存档 | 用户指定的私有 prefix |
| 游戏副本 | 用户合法持有的游戏数据 | 本机 games/ 或明确引用的位置 |
| 原生入口 | 启动器二进制、图标、封面、游戏 ID | 用户生成的 `.app` |

运行时按 ID 固定，登记 Wine 与 wineserver 的 SHA-256。`doctor` 检测二进制被替换后要求用户重新核验；这不是完整运行时供应链签名验证。框架目录只检查存在，不能证明全部动态库完整。运行时应从其官方发行渠道安装并核对许可与指纹。

## 公共清单字段

未知字段和重复 JSON 键拒绝。清单上限 1 MiB，UTF-8；`wgfm validate` 是实际校验入口。

| 字段 | 约束 / 默认 |
|---|---|
| schema_version | 必需，整数 1 |
| id | 必需，1–64 字符，小写字母、数字、下划线、连字符 |
| name | 必需，有效 macOS 应用名称，最多 100 字符 |
| version | 必需，1–3 段数字，例如 `1.0` |
| executable | 必需，游戏目录内的 POSIX 相对路径，拒绝 `..` / 盘符 / 外部链接 |
| working_directory | 游戏目录内的相对路径，默认 `.` |
| arguments | 最多 128 个字符串，默认 `[]`；原样传给进程，不使用 shell |
| environment | 字符串键值对象，默认 `{}`；拒绝密码/令牌类键、运行时/注入/路径覆盖 |
| steam_app_id | 可选，1–10 位数字字符串；存在时必须配置客户端及同位数 probe |
| readiness_timeout_seconds | 5–300 秒，默认 120；包含探测进程执行时间 |
| notes | 可选的人类说明，不参与启动 |

游戏数据中的可执行文件必须为 Windows x86/x64 PE。位数检查不等于目标 Wine 支持相应架构。Steam probe 必须同位数，其运行目录为游戏 exe 所在目录。

## 导入和构建

`game-add` 先验证路径、PE、共享会话一致性及必要文件，再执行导入。APFS 上尝试 `/bin/cp -cR`；非 APFS 或失败时回退到普通复制。注册写入失败会回滚本次新副本。重复 ID 或已有目标目录均拒绝覆盖。

`--adopt-existing` 放弃独立副本，明确引用既有游戏目录。不会复制 Steam、prefix 或凭据。默认各游戏使用独立 prefix；显式提供相同 prefix 才会共享会话。不要继续混用未纳入本组件的旧启动器，它们不会遵守本组件的会话锁。

构建编译本机架构 Cocoa 程序，缓存按源码和架构分开。应用暂存在输出目录中，完成图像转换与 ad-hoc 代码签名校验后才移动到目标位置。`--replace` 保留前一版，移动失败时恢复旧应用。开发者 ID 签名与 Apple 公证不在当前本机构建流程中。

## 启动状态

1. 读取本机 profile、runtime 和会话一致性记录。
2. 对 prefix 取得独占文件锁。CLI 维护命令使用相同锁。
3. 继承少量标准系统环境变量，构建 Wine 环境，仅选择一种同步模式。
4. Steam 游戏先调用只做 `SteamAPI_Init` 的 probe；已就绪时直接启动。
5. 未就绪才请求 Steam 后台启动。probe 每次最多 8 秒，失败后退避，整体受实际截止时间约束。取消只终止当前 probe，不终止账号客户端。
6. 启动原版 exe，参数为数组。主窗口在启动后收起，启动器持锁等待游戏结束。它不逐帧轮询，不参与渲染或输入。
7. 游戏退出后启动器结束并释放锁；异常退出显示本机错误提示。

`sync` 维护操作在同一把锁中先请求 Steam 正常关闭，留出最多 8 秒等待，再仅对指定 prefix 执行 `wineserver -k/-w`，然后更新共享注册。它会结束该 prefix 里的 Windows 进程，应先退出游戏。跨文件维护中途断电可造成不一致，此时启动器拒绝启动，应重新登记/恢复相应私有注册，而不是猜测环境继续运行。

## 性能和兼容性边界

组件降低的是包装与维护成本：原生入口、复用运行时、APFS 克隆、受限日志、失败退避。MSYNC 是否增益、D3D 如何转换、游戏是否稳定，仍需按固定场景实测。没有运行时支持检测的同步模式不会自动尝试启用。

不会修改 exe/DLL、破解 DRM、替换反作弊、修改 Steam 登录状态文件，或强制游戏画质/帧率参数。默认也不附加任何图形注入层。DirectX 游戏应另外选择经过验证的兼容运行时，再按这里的同一清单/测试流程接入。

## 可选的游戏内主菜单外观

`menu-background` 是独立、明确调用的 GoldSrc 资源适配器，只接受 `hl.exe -game cstrike/czero`。它在注册游戏的 mod 目录中覆盖 `resource/BackgroundLayout.txt` 和 `resource/HD_BackgroundLayout.txt`，指向新增的唯一图片目录。原版 TGA、加载布局、地图、游戏二进制均不替换。图片居中裁切，原生 CoreGraphics 缩放与裁切，输出不压缩的 24 位 TGA，按原版 VGUI 布局加载。

备份先于游戏资源变更写入，写入失败回退；恢复支持原文件不存在和布局提交中断。恢复前检查原始备份与当前布局的指纹，拒绝覆盖未知的手工布局修改。恢复后清理未被更改的生成图片，保留用户手工改过的图片。该操作同样取得会话锁，运行中的游戏不能修改背景。
